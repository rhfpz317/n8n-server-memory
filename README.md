## n8n 到底需要什么配置？

**2GB 内存是底线，4GB 才从容。** n8n 官方推荐的自托管方式是 Docker，跑起来后你要养着 Node.js 主进程、SQLite 数据库和各个工作流的执行环境。社区和测评的普遍口径是：n8n 至少要 2GB 内存，想稳定跑多工作流建议 4GB 起步。如果你的工作流就是每天定时抓个数据、发个通知，2 核加 2GB 内存的机器完全够用；要做大量并发 webhook、用代码节点处理大文件，直接选 4GB。

硬盘和流量反而不挑。n8n 处理的主要是 API 请求的文本数据，几十 GB SSD 用不完，每月 1TB 流量对绝大多数人来说是天文数字。

比内存更容易被忽略的是**虚拟化架构**。Docker 需要独立内核的 KVM 虚拟化才能跑得干净，一些超低价商家卖的 OpenVZ 或 LXC 架构机器，装 Docker 经常报各种内核相关的错。下单前确认商家是 KVM，能省掉一整类疑难杂症。RackNerd 全线是 KVM，这是它适合跑 n8n 的前提。

顺带一提，1GB 档位加个 swap 能把 n8n 拉起来，但执行并发一高就卡。为了一年省十几美元忍这个，不值，正式用直接跳过 1GB。

## 开通后：半小时部署 n8n 的关键步骤

RackNerd 开机后拿到的是一台干净的 root 机器，部署路径是现成的，完整流程照着 n8n 中文社区的图文教程走即可。下面只列最容易出错的几个关键点：

1. **装系统选 Debian 12 或 Ubuntu 24.04**，然后装 Docker。想省事可以直接装 1Panel 面板，用图形界面管理容器、反代和证书。
2. **先建数据目录再起容器**，把宿主机目录挂载到容器内的 `/home/node/.n8n`。这一步比任何环境变量都重要：不挂载的话，下次升级 n8n 版本，工作流和凭证会被清空，而且没挂载过的数据无法补救。
3. **环境变量按这个表配**（n8n 监听 5678 端口）：

| 环境变量 | 示例值 | 作用 |
| --- | --- | --- |
| N8N_HOST | n8n.example.com | 你的访问域名 |
| WEBHOOK_URL | https://n8n.example.com/ | 对外回调地址，必须带协议头 |
| GENERIC_TIMEZONE | Asia/Shanghai | 定时任务按这个时区跑 |
| N8N_PROXY_HOPS | 1 | 反向代理层数 |
| N8N_RUNNERS_ENABLED | true | 新版任务分离特性，工作流报错可先关掉 |

4. **反向代理加 HTTPS**。用 1Panel 的话建一个反向代理网站指向 `localhost:5678/`，注意地址结尾的斜杠不能少，否则 WebSocket 连接会出问题；如果用 Caddy，配置只需三行，证书全自动：


n8n.example.com {
    reverse_proxy localhost:5678
}


5. **初始化账号务必记牢。** 你注册的第一个账号就是超级管理员，而私有部署的 n8n 无法找回密码，忘了只能删库重装。这个提醒教程里都有，但每年照样有人踩。

部署完顺手做两件安全的事：SSH 改用密钥登录，防火墙只放行必要端口。备份也简单：把挂载的数据目录定期打包下载，Workflow、凭证、执行记录全在里面，换机器时整个目录搬走就能恢复。

## 常见问题

**1GB 内存的机器能跑 n8n 吗？**
能启动，但不建议。加 swap 之后勉强能用，并发一高就卡死，一年省十几美元换这种体验不划算。1GB 档留给纯测试用途，正式跑选 2GB 起。

**每月 3TB 流量够吗？**
n8n 传输的主要是 API 请求和响应的文本数据，跑一年可能都用不了几十 GB。除非你的工作流每天搬运大文件，否则不用担心流量。

**在国内打开面板会不会很慢？**
偶尔打开编辑器，洛杉矶机房一般几秒内能加载完。工作流执行发生在服务器之间，和你在哪无关。真在意的话，年付反正便宜，面板慢点忍了也行。

**需要备案吗？**
服务器在海外就不涉及备案，域名也不必在国内注册商购买。这也是海外 VPS 对 n8n 用户的一大好处。
